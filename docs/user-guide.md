## 摘要

本手册描述 **Evidence-Ladder**（大模型应用黑盒安全评测平台）的界面功能与标准操作流程。平台通过自动化红队测试，对 Prompt 注入、系统提示词泄露、越狱、信息泄露等风险进行可复现、可审计的评估；支持多类目标接入、多攻击引擎与四元组对照实验。阅读本手册前，请确保已完成部署与 API 配置（参见《安装配置说明》）。

## 1. 术语与缩写

| 术语 / 缩写 | 说明 |
|-------------|------|
| **Case** | 一次攻击用例在四元组协议下的聚合单元，可含多条变体响应 |
| **四元组（Quartet）** | Attack / Clean / Quoted Attack / Benign Distractor 四组对照变体 |
| **Canary Token** | 预埋在 system prompt 中的唯一标记，用于高置信度检测提示词泄露 |
| **PAIR** | Prompt Automatic Iterative Refinement，迭代式提示优化攻击 |
| **TAP** | Tree of Attacks with Pruning，树搜索与剪枝攻击 |
| **OWASP LLM Top 10** | OWASP 大模型应用十大风险框架（如 LLM01 提示注入） |
| **裁判（Judge）** | 平台内用于判定攻击是否成功的分析模型（与“人工复核”区分） |

## 2. 系统概述

### 2.1 产品定位

Evidence-Ladder 面向 **真实上线场景** 的大模型应用安全测试：不限于“测底模”，而是评估商用模型在业务 system prompt、接口与工具链环境下的 Prompt 注入、越权服从、敏感信息泄露等风险。评测结果强调 **可复现、可比较、可审计**。

### 2.2 核心能力概览

| 能力域 | 说明 |
|--------|------|
| **目标类型** | 内置靶场、OpenAI 兼容 API、Claude 原生、自定义 HTTP、Adapter 适配器 |
| **攻击类别** | 七类：Prompt Injection、System Prompt Extraction、Jailbreak、Information Disclosure、Indirect Injection、Excessive Agency、Denial of Service（详见《攻击模板库说明》） |
| **高级引擎** | Crescendo、MSJ、ICE、FITD、TAP、PAIR、Self-Explanation、Mutation 等（与模板协同，见该文档第 6 节） |
| **四元组对照** | 降低“仅讨论攻击文本”与“真实执行攻击”的混淆，支撑结构化裁决 |
| **裁决输出** | 除成功/失败外，可输出执行模式、黑盒结果、行为标签等 |
| **人工复核** | 对攻击已命中场景提供“确认为真实漏洞 / 误报 / 重置”工作流 |

### 2.3 三层检测体系

| 层次 | 检测焦点 | 典型用法 |
|------|----------|----------|
| **底模层** | 模型是否易被带偏、越权服从 | OpenAI 兼容目标直连第三方模型 |
| **提示词规则层** | 业务 system prompt 与隐藏规则是否可被套取 | 配置 system prompt 与 Canary Token |
| **应用接口层** | 真实业务 API 是否放大泄露或误执行风险 | Adapter 对接企业接口 |

## 5. 新建扫描

### 5.1 基本项

1. **任务名称**：建议使用可检索的命名规范（如 `环境-模型-日期`）。  
2. **目标类型**：决定请求如何发出及凭据如何解析（见下节）。

### 5.2 目标类型说明

**内置靶场（builtin_vulnerable）**  
内置聊天靶标，防护等级 Level 1–4，用于链路验证与模式理解，不代表真实业务密钥泄露。

**OpenAI 兼容（openai_compatible）**  
兼容 OpenAI Chat Completions 的 HTTP API。支持从「模型供应商」选择已保存凭据并拉取模型列表，或手动填写 Base URL、模型名与密钥。可选填写 **System Prompt** 与 **Canary Tokens** 以覆盖「提示词规则层」测试。

**Claude（claude）**  
经 Anthropic SDK 调用。需 Anthropic API Key 或已配置的 Claude 类型供应商；适合多轮攻击（如 Crescendo）。

**适配器（adapter）**  
通过已保存的 Adapter 定义请求模板、认证、响应解析与可选探针；支持运行时变量注入。

**自定义 HTTP（custom）**  
向指定 URL 以约定 JSON 形态投递载荷（如 `message` / `history`），可配自定义 Header。

### 5.3 攻击类别与 OWASP 映射（节选）

| 类别 | 说明 | OWASP 参考 |
|------|------|------------|
| Prompt Injection | 覆盖或篡改系统指令 | LLM01 |
| System Prompt Extraction | 套取系统提示词或等效隐藏规则 | LLM07 |
| Jailbreak | 绕过安全对齐 | LLM01 |
| Information Disclosure | 敏感信息不当输出 | LLM02 |
| Indirect Injection | 经检索/工具等间接通道注入 | LLM01 |
| Excessive Agency | 越权操作或工具滥用 | LLM08 |
| Denial of Service | 资源耗尽或服务不可用 | LLM04 |

选择「全部」即覆盖当前已加载模板类别。

### 5.4 高级攻击模式与四元组策略

高级面板可启用 Crescendo、MSJ、ICE、FITD、TAP、PAIR、Self-Explanation、Mutation 等；各引擎与模板的关系见《攻击模板库说明》第 6 节。

**四元组控制模式**：

| 模式 | 行为 |
|------|------|
| Full | 每攻击运行完整四变体，对照最强 |
| Adaptive | 在明确失败场景下跳过部分对照以节省时间 |
| Off | 仅攻击变体，无对照，速度优先 |

### 5.5 演示预设

页面预设可一键载入演示用扫描配置（如金融客服、HR RAG 场景），用于路演或培训；提交前请核对目标 URL 与密钥策略是否符合组织规范。

## 7. 扫描结果分析

### 7.1 视图

- **Case 视图**：以 Case 为主，展示四元组及控制组结论  
- **旧版结果视图**：以单条 `AttackResult` 为粒度，便于兼容历史数据  

### 7.2 筛选与导出

支持按判定状态、攻击类别等筛选；支持导出 CSV 供线下分析。

### 7.3 判定标签（界面展示）

| 界面标签 | 含义（概要） |
|----------|----------------|
| 通过 | 当前裁决下攻击未构成成功利用（或已归一为通过） |
| 规则验证 | 规则或强信号命中后的确认态 |
| AI 疑似 | 模型裁判倾向存在风险，置信度有限 |
| 待人工复核 | 自动裁决不确定，建议人工介入 |
| 人工确认 / 误报 | 经人工复核后的终态（以实际枚举为准） |

具体枚举与图标以当前版本 UI 为准。

### 7.4 Case 详情字段

展开后可包含：四元组与业务验证状态、控制组分析摘要、AI 判定理由、变体请求/响应、遗留结果摘要（若存在）。**人工操作按钮**仅在「攻击已成功」等需裁决的场景展示（产品逻辑以当前代码为准）。

### 7.5 控制组评估枚举（示例）

| 枚举 | 含义 |
|------|------|
| attack_delta_supported | 攻击变体相对对照组存在可区分的行为差异 |
| discussion_supported | 主要表现为讨论攻击而非执行 |
| controls_inconclusive | 对照证据不足以下结论 |
| controls_missing | 未运行或未完整运行对照 |

## 10. 适配器

Adapter 用于描述「如何把平台标准载荷映射为业务 HTTP 请求并解析响应」。配置项包括：Base URL、传输模式、认证、Body 模板（如 `{{prompt}}`、`{{runtime.*}}`）、响应提取、可选会话与探针。配置后应使用内置测试验证连通与字段提取正确性。

## 11. 对话试验场

用于在正式扫描前做 **单会话** 连通性与行为探测；配置项与新建扫描中的目标配置类似。

---

## 12. 对比分析

选择多个已结束扫描，对比综合评分、成功率、分类雷达等，用于版本对比或不同模型/配置对照。

---

## 13. 裁判校准

用于度量 **自动裁判模型** 与人工金标准的一致性：批量采样 → 标注金标准 → 运行评估 → 查看 Precision / Recall / 误报相关指标及分维度拆解。适用于对裁判漂移敏感或需对外证明评测可信度的场景。

## 15. 常见问题

**Q：提示缺少 API Key**  
在「设置」中至少启用一个供应商并保存有效密钥，或在扫描表单中按目标类型填写密钥。

**Q：大量结果为「通过」**  
可能表示目标防御有效，或目标/类别/引擎配置偏保守。可尝试提高靶场难度、启用更强攻击引擎，或复核目标 URL 与模型是否一致。

**Q：分析文本为英文**  
裁判与部分目标回复语言受模型与 prompt 语言影响；可在目标 system prompt 中指定业务语言。

**Q：四元组各变体含义**  
Attack 为攻击载荷；Clean 为不含攻击的基线；Quoted Attack 将攻击作为引用数据；Benign Distractor 为无害干扰。通过对比可区分「执行攻击」与「仅讨论攻击文本」。

**Q：综合评分区间如何理解**  
评分为平台自定义风险度量，区间划分以界面图例为准；对外汇报建议同时给出规则验证率、人工确认率等多指标，避免单一数字误导（参见项目 README「汇报口径」）。
