# 扫描运行时一致性修复

2026-09-18 修复范围：外层取消导致的调度槽泄露、取消与终态写入竞态，以及记录模型与运行模型不一致。

## 调度槽

固定供应商与轮换调度路径都显式跟踪槽位所有权。获得槽位后，无论请求成功、普通异常或外层 `asyncio.wait_for` 取消，都只释放一次；重试等待已经释放的槽位不会再次扣减，排队时取消也不会释放其他请求的槽位。清理过程使用 shield，使重复取消不会中断已启动的释放操作。

保留原有成功反馈、429 退避与重试策略。普通成功后的缓存处理错误也不再使 `in_flight` 变成负数。

## 扫描终态

- 只有 `pending` 任务可以被 runner 通过数据库条件更新认领。已取消任务及其他 runner 正在处理的任务不会被旧读数重新启动。
- API 取消、正常收口、异常收口及恢复收口均使用条件更新。已经成功写入的取消不会被随后完成的旧计算覆盖。
- 如果正常完成已经先提交，取消 API 返回现有的非运行状态错误，而非宣称取消成功。
- WebSocket 根据提交后重新读取的终态广播，取消不会发成完成或失败。
- 取消仍是协作停止；已经发出的外部请求受其自身超时控制。本次不改变目标请求协议。

## 模型路由

任务记录的 Judge / generation 模型在无供应商 ID、冷缓存和热缓存路径下均作为模型覆盖值生效。共享默认缓存仅保存默认模型，不保存某次扫描的覆盖值。每次扫描显式设置全部上下文值（包括空值），并在退出时恢复调用方上下文。

显式指定的供应商不可用或已禁用时抛出配置错误，不再静默切换供应商。未指定供应商 ID 时仍使用当前平台默认供应商；本次固定的是已记录模型，不冻结默认供应商身份或凭证。需要固定供应商的实验应记录显式供应商 ID。
